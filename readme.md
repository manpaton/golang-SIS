# SIS: Password Checker (CP2 - Concurrent Processing)

Маленькое Go-приложение для валидации и анализа паролей.
Во второй версии (CP2) добавлена многопоточная обработка задач (Worker Pool).

## Запуск
    go run .

## Тесты
    go test ./...
    go test -race ./...

## Архитектура Concurrency (Worker Pool)
Приложение использует паттерн Worker Pool для параллельной обработки задач:
- **Количество воркеров:** 2 горутины.
- **Очередь (Task Queue):** Буферизованный канал `chan int` вместимостью 10 задач.
- **Поведение при переполнении:** Если очередь заполнена (10 задач в канале + 2 в обработке), новые задачи не блокируют поток, а моментально отклоняются с ошибкой `ErrQueueFull` (Option A).
- **Синхронизация:** Доступ к in-memory хранилищу задач (`map`) защищен с помощью `sync.RWMutex`, что исключает состояние гонки (data races).

## Жизненный цикл задачи
    pending -> queued -> processing -> completed

- `pending`: задача создана, но ещё не отправлена в очередь.
- `queued`: задача успешно добавлена в канал и ожидает воркера.
- `processing`: воркер взял задачу и выполняет анализ.
- `completed`: анализ завершен, результат записан.

## Безопасная остановка (Graceful Shutdown)
При завершении работы вызывается метод `Stop()`. Он переводит флаг `stopped = true` (запрещая принимать новые задачи), закрывает канал очереди (`close`) и использует `sync.WaitGroup`, чтобы дождаться успешного завершения всех задач, которые уже были приняты в очередь.

## Создание, отправка и получение задач
- **Создание (`Create`):** проверяет пароль по правилам валидации (длина от 8 до 30 рун, без пробелов и не-ASCII/непечатных символов, обязательны заглавная буква и символ)[cite: 8], выдаёт уникальный `ID`[cite: 5] и сохраняет задачу в памяти со статусом `pending`[cite: 5, 7].
- **Отправка в очередь (`Submit`):** кладёт `ID` задачи в буферизованный канал очереди (ёмкость 10)[cite: 4, 5] и переводит задачу в `queued`[cite: 5]. Вызов неблокирующий: функция сразу возвращает управление, не дожидаясь окончания проверки пароля[cite: 2]. Если канал полон — моментально возвращается `ErrQueueFull`[cite: 4, 5].
- **Чтение (`Get`):** безопасно читает задачу из хранилища под `RWMutex` и возвращает копию структуры, чтобы внешний код не испортил внутренние данные[cite: 5].

## Переходы статусов и обработка ошибок
- **Основной путь:** `pending` -> `queued` -> `processing` -> `completed`[cite: 4, 5, 7].
- **Защита от повторного/неверного `Submit`:** отправить в очередь можно только задачу в статусе `pending`[cite: 5]. Если задача уже `queued`, `processing` или `completed`, `Submit` вернёт `ErrInvalidTransition`[cite: 5, 10].
- **Остановка сервиса (`Stop`):** после вызова `Stop()` новые вызовы `Submit` отклоняются с ошибкой `ErrStopped`[cite: 5, 10].
- **Ошибка при обработке (`process`):** если процессор вернёт ошибку, задача не помечается как `completed`, а статус откатывается в `pending` без записи результата[cite: 5].
